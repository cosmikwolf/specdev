# egui Store Concepts → Rust Implementation

This file defines how egui store spec concepts map to Rust language
constructs. Stores hold app-level state that outlives any individual
view.

## Source Directory Placeholder

Every `src/stores/...` path in this file is shorthand for `<source_dir>/stores/...`, resolved by `/spec-gen`: `<packages.<name>.source_path>/src/stores/` when the module carries a `package` key, else `<source.root>/stores/`.

## Extraction YAML Schema

Code generation reads the per-store YAML produced by `specdev-analyzer
extract` (output path: `<out>/stores/<StoreName>.yaml`):

| YAML path | Description |
|---|---|
| `name` | PascalCase store name (also the struct name) |
| `description` | one-line store purpose (becomes doc comment) |
| `fields[]` | `{name, type, default?, description?, derived?}` |
| `persisted` | boolean — whether to load/save via `eframe::Storage` |
| `satisfies[]` | requirement ids this store satisfies |

---

## Store → Struct with Derived Traits

Each store generates a single public struct:

```rust
#[derive(Debug, Clone)]
pub struct <StoreName> {
    pub <field_snake>: <Type>,
    // ...
}
```

- Field names stay snake_case; types come from `type_map.rust` in the
  domain config (e.g., `Integer` → `i32`, `Boolean` → `bool`).
- Each field is `pub` unless `derived: true` — derived fields are
  private and exposed via a read-only accessor method.
- Derive `Clone` by default; add `PartialEq`, `Eq` when every field type
  supports them (useful for change detection in views).
- When `persisted = true`, also derive
  `serde::Serialize, serde::Deserialize` and ensure every field's type
  implements those (validate.md check #7 enforces this).

---

## Defaults → `Default` Impl

Emit an explicit `impl Default`:

```rust
impl Default for <StoreName> {
    fn default() -> Self {
        Self {
            <field_snake>: <default-expr>,
            // ...
        }
    }
}
```

- Field `default` in the spec is pasted as the Rust expression. When
  omitted, use the type's `Default::default()` (zero for numbers, empty
  for collections, `None` for Option).
- Derived fields use the same recomputation their accessor uses — they
  are not independently defaulted.

---

## Derived Fields → Accessor Methods

When a field has `derived: true`, it is a computed value, not a stored
one. Options:

1. Keep the field as a cache and recompute on mutation (preferred when
   the field is read far more often than written).
2. Omit the field entirely and emit an accessor:

```rust
impl <StoreName> {
    pub fn <derived_snake>(&self) -> <Type> {
        // TODO: compute from source fields
    }
}
```

The generator emits option 2 as the default; a human can promote to
option 1 if profiling shows the recompute cost matters. External writes
to derived fields are an error (validate.md check #8).

---

## Persistence → `eframe::Storage` Hooks

When `persisted = true`, the store participates in eframe's startup /
shutdown persistence. The generated `AppState` calls into each persisted
store:

```rust
impl <StoreName> {
    pub const STORAGE_KEY: &'static str = "<store_snake>";

    pub fn load(storage: &dyn eframe::Storage) -> Self {
        eframe::get_value(storage, Self::STORAGE_KEY).unwrap_or_default()
    }

    pub fn save(&self, storage: &mut dyn eframe::Storage) {
        eframe::set_value(storage, Self::STORAGE_KEY, self);
    }
}
```

- `STORAGE_KEY` is the store name snake_cased; override only if needed
  to avoid collisions.
- `eframe::get_value` / `set_value` require the `persistence` feature
  on `eframe` in `Cargo.toml`.
- `load` falls back to `default()` on missing / malformed data — never
  panic at startup.

Non-persisted stores omit these methods entirely and initialize via
`<StoreName>::default()`.

## File Layout → `src/stores/<snake>.rs`

Each store generates:

- `src/stores/<store_snake>.rs` — struct, `Default` impl, optional
  persistence methods, accessor methods for derived fields.
- Re-export in `src/stores/mod.rs`:
  `pub mod <store_snake>; pub use <store_snake>::<StoreName>;`

---

## Ownership → Owned by `AppState`

The top-level `eframe::App` struct (generated by `gen-app.md`) owns one
instance of every store declared in `specs/stores/`. Views receive `&`
or `&mut` references via their `show` signatures; stores are never
accessed through globals or `static`s.

When two views need to mutate the same store in the same frame, the
parent view that owns both sub-views arranges the call order; egui's
single-threaded render ensures there is no aliasing concern.

---

## Naming

- Store name is PascalCase and matches the filename (`CounterStore.toml`
  → `pub struct CounterStore`).
- Variable name for an instance is the snake_case form
  (`counter_store`).
- Field names stay snake_case; public fields are preferred over
  getter/setter boilerplate.
